## Что проверять

### Архитектура
- Нет дублирования логики
- Принцип единственной ответственности (SRP)
- Слабая связанность между модулями
- Новый код вписывается в существующую архитектуру

### Безопасность
- Нет SQL-инъекций (используются параметризованные запросы)
- Входные данные валидируются
- Секреты/ключи не хардкодятся
- Проверка прав доступа

### Тесты
- Покрыты ли новые ветвления
- Тесты не хрупкие (не тестируют реализацию)
- Есть ли негативные сценарии

### Производительность
- N+1 запросы
- Нет блокирующих вызовов там где нужна асинхронность
- Не загружается лишнее

## Формат ответа

Для каждого замечания:
- CRITICAL: блокирует merge
- WARNING: желательно исправить
- NIT: на усмотрение автора
