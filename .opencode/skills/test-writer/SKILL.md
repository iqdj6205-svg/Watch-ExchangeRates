## Процесс

1. Найти существующие тесты в проекте — определить фреймворк, стиль, паттерны (mocking, fixtures)
2. Определить тип теста:
   - Unit — изолированная логика
   - Integration — взаимодействие модулей
   - E2E — пользовательский сценарий
3. Написать тесты следуя найденному стилю

## Правила

- Использовать те же библиотеки/утилиты что в проекте
- Тестировать поведение, а не реализацию
- Один тест — один сценарий
- Названия тестов читаемые: `test_<что>_<когда>_<результат>`
- Добавить негативные сценарии (ошибки, граничные случаи)
- После тестов запустить их и показать результат
