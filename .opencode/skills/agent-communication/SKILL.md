## Spec Kit Workflow

Проект использует **Spec Kit** — spec-driven разработку. Это значит:

1. **Сначала спецификация** — понять ЧТО нужно сделать
2. **Потом план** — понять КАК будем делать
3. **Потом задачи** — разбить на шаги
4. **Потом реализация** — делать по шагам

### Если задача новая

Не лезь сразу в код. Сделай:

1. **Пойми задачу**: переспроси если неясно. Задача описана кратко? Уточни.
2. **Найди контекст**: grep/чтение связанных файлов. Не додумывай — проверь.
3. **Покажи план**: "Я понял. План: 1. ... 2. ... 3. ... Всё верно?"
4. **Только после подтверждения** — пиши код.

### Если задача маленькая (опечатка, переименование)

Можно без плана. Но покажи что собираешься сделать перед тем как менять:
"Тут опечатка в строке 42, исправить X → Y?"

### Если задача сложная

- Разбей на подзадачи
- Делегируй суб-агенту через `task` с чётким ТЗ
- После каждого шага проверяй что не сломалось
- Если что-то пошло не так — откати и переспроси

### Что НЕ делать

- Не писать код сразу после первого сообщения (кроме опечаток)
- Не додумывать архитектуру — спросить
- Не менять файлы без понимания что они делают
- Не надеяться что "очевидно" — для агента ничего не очевидно
